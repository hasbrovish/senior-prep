## OA BATTLE STRATEGY

### By Platform
| Platform | Companies | Format | Your Strategy |
|----------|-----------|--------|---------------|
| HackerRank | Amazon, Goldman, Microsoft, Adobe, Flipkart | 2-3 DSA, 90min | Read ALL problems first, pick easiest, partial credit > 0 |
| LeetCode | Google (custom), Atlassian | 2 DSA, 60min | Clean code over brute force; Google reads your code |
| Internal | CRED, PhonePe, Swiggy | Varies | Time-box: 30min per problem, never stuck >15min |

### OA Mindset Protocol
```
0-5 min:   Read ALL problems. Categorize: Easy/Hard/Impossible
5-15 min:  Solve easiest problem completely. Get that 100%.
15-30 min: Tackle medium problem — BRUTE FORCE FIRST, then optimize
30-60 min: Optimize medium + attempt hard (partial credit)
60-90 min: If stuck: write pseudocode. Many systems give partial marks.
Never:     Spend 45+ min on one hard problem with 2 easy ones unsolved.
```

### Company-Specific OA Patterns
```
Amazon:   Trees + OOP questions + LP essay. Tip: LP essay = STAR format, 3-4 sentences each part.
Goldman:  DP + Graphs + ONE concurrency question. Read about thread-safety before their OA.
Adobe:    Arrays + DP + Strings. Tip: They like implementation-heavy questions (simulate X).
PhonePe:  DP + SQL. Tip: Brush up GROUP BY, window functions, HAVING vs WHERE.
Flipkart: Arrays + DP + OOP. Tip: Code quality matters — use meaningful variable names.
Microsoft:Arrays + Trees + DP. Tip: Comment your approach. They like communicative code.
```
