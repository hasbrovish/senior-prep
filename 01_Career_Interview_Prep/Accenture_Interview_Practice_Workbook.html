Q1
Easy🔥 Very Frequent

What are the 4 pillars of OOPs? Explain each with a real-world example from your project.

Expected Answer

Encapsulation: Wrapping data + methods together, restricting direct access. Example: In GSTN, taxpayer details are encapsulated with private fields and accessed via getters/setters. Sensitive data like PAN is never directly exposed.

Abstraction: Hiding implementation complexity. Example: A TaxCalculationService interface exposes calculateGST() — the caller doesn't know if it uses CGST+SGST or IGST logic internally.

Inheritance: Child class inherits parent properties. Example: BaseAuditEntity has createdDate, modifiedDate — all entities like Invoice, Return extend it.

Polymorphism: Same method behaves differently. Example: PaymentProcessor.process() — UPIPayment, CardPayment, NetBanking each override differently.

Q2
Medium🔥 Very Frequent

What is the output of this code? Explain why.

class Animal {
    void sound() { System.out.println("Animal sound"); }
}
class Dog extends Animal {
    void sound() { System.out.println("Bark"); }
    void fetch() { System.out.println("Fetching..."); }
}
public class Main {
    public static void main(String[] args) {
        Animal a = new Dog();
        a.sound();     // Line 1
        // a.fetch();  // Line 2 — What happens if uncommented?
    }
}

Expected Answer

Line 1 Output: Bark

This is runtime polymorphism (dynamic method dispatch). The reference type is Animal, but the actual object is Dog. At runtime, JVM calls Dog's sound() method.

Line 2: Compilation error! — The reference type is Animal which doesn't have fetch(). Compiler checks the reference type, not the object type. You'd need to cast: ((Dog)a).fetch();

💡 Interview Tip: Accenture Round 2 commonly gives 3-4 such code snippets. The trick is always: compiler checks reference type, JVM checks object type at runtime.

Q3
Medium🔥 Very Frequent

Explain HashMap internal working. What happens when two keys have the same hashCode?

Expected Answer

Internal structure: HashMap uses an array of Node (bucket array). Each Node has: key, value, hash, next.

put() process:

  • Calculate hash of key → determine bucket index via hash & (n-1)
  • If bucket is empty → place new Node
  • If bucket occupied (collision) → compare hash and equals()
  • If same key → update value; if different key → add to linked list

Java 8 optimization: When linked list in a bucket exceeds 8 nodes (and array size ≥ 64), it converts to a Red-Black Tree (O(log n) instead of O(n)).

Hash collision: Two different keys with same hashCode go to same bucket. They're stored as linked list nodes, distinguished by equals() method.

Load factor (0.75): When 75% of array is filled, HashMap doubles in size (rehashing).

Q4
Medium🔥 Very Frequent

HashMap vs ConcurrentHashMap — What are the key differences?

Expected Answer

Thread Safety: HashMap is NOT thread-safe. ConcurrentHashMap IS thread-safe.

Null keys/values: HashMap allows 1 null key + multiple null values. ConcurrentHashMap allows NEITHER null keys nor null values.

Locking mechanism: ConcurrentHashMap uses segment-level locking (Java 7) / CAS + synchronized on individual bucket (Java 8). Only the specific bucket is locked, not the entire map.

Performance: ConcurrentHashMap is slightly slower for single-threaded use but much faster in multi-threaded scenarios compared to Collections.synchronizedMap().

Iterator: HashMap's iterator is fail-fast (throws ConcurrentModificationException). ConcurrentHashMap's is fail-safe (works on a snapshot).

When to use: Use ConcurrentHashMap in multi-threaded applications like GSTN where multiple threads process tax filings simultaneously.

What is the difference between == and .equals() in Java? What is the output?

String a = new String("Hello");
String b = new String("Hello");
String c = "Hello";
String d = "Hello";

System.out.println(a == b);       // ?
System.out.println(a.equals(b));  // ?
System.out.println(c == d);       // ?
System.out.println(a == c);       // ?

Expected Answer

a == b → false — Two different objects on heap

a.equals(b) → true — Content comparison

c == d → true — Both point to same String Pool reference

a == c → false — 'a' is on heap, 'c' is in String Pool

Key concept: == compares references (memory addresses). .equals() compares content. String literals go to String Pool (shared). new String() creates a new heap object.

What is the Object class? Name its important methods.

Expected Answer

java.lang.Object is the root class of all Java classes. Every class implicitly extends Object.

Key methods:

  • toString() — String representation of object
  • equals(Object o) — Content equality check

Q7
MediumFrequent

Explain Deep Copy vs Shallow Copy with examples.

Expected Answer

Shallow Copy: Creates a new object but copies references to the same internal objects. Changes to nested objects affect both copies.

Deep Copy: Creates a new object AND recursively copies all nested objects. Completely independent copies.

// Shallow copy — both point to same Address object
Employee e1 = new Employee("Hasbrovish", new Address("Pune"));
Employee e2 = e1.clone(); // shallow
e2.getAddress().setCity("Mumbai");
// e1.address is also "Mumbai" now! ❌

// Deep copy — independent Address objects
Employee e2 = new Employee(e1.getName(), 
    new Address(e1.getAddress().getCity())); // deep
e2.getAddress().setCity("Mumbai");
// e1.address is still "Pune" ✅

Ways to deep copy: Copy constructor, Serialization/Deserialization, using libraries like Apache Commons BeanUtils, or manually cloning nested objects.

What are access modifiers in Java? Can a subclass in a different package access a protected member?

Expected Answer

private: Only within the same class

default (no keyword): Same class + same package

protected: Same class + same package + subclasses (even in different packages)

public: Accessible everywhere

Yes, a subclass in a different package CAN access protected members — but only through inheritance, not through an instance of the parent class.

// package B
public class Child extends Parent {
    void test() {
        System.out.println(this.x);    // ✅ Works via inheritance
        Parent p = new Parent();
        // System.out.println(p.x);    // ❌ Compile error!
    }
}

What is the difference between final, finally, and finalize?

Expected Answer

final: A keyword — final variable (constant), final method (can't override), final class (can't extend). Example: String class is final.

finally: A block in exception handling — always executes whether exception occurs or not. Used for cleanup (closing DB connections, streams).

Q10
Medium

Explain Exception Hierarchy. What is the difference between checked and unchecked exceptions?

Expected Answer

Hierarchy: Throwable → Error (JVM issues like OutOfMemoryError) | Exception → RuntimeException (unchecked) | Other Exceptions (checked)

Checked exceptions: Compiler forces handling (try-catch or throws). Examples: IOException, SQLException, FileNotFoundException. These represent recoverable conditions.

Unchecked exceptions: Extend RuntimeException. Compiler doesn't force handling. Examples: NullPointerException, ArrayIndexOutOfBoundsException, ClassCastException. These represent programming errors.

Best practice: Use checked exceptions for recoverable situations, unchecked for programming bugs. In Spring Boot, use @ControllerAdvice for global exception handling.

Q11
Medium

What is immutability? How do you create an immutable class in Java?

Expected Answer

An immutable object cannot be modified after creation. String is the classic example.

Rules to create immutable class:

  • Declare class as final (prevent subclassing)
  • Make all fields private final
  • No setter methods
  • Initialize all fields via constructor
  • Return deep copies of mutable fields (like Date, List) in getters
public final class Employee {
    private final String name;
    private final List<String> skills;
    
    public Employee(String name, List<String> skills) {
        this.name = name;
        this.skills = new ArrayList<>(skills); // defensive copy
    }
    public String getName() { return name; }
    public List<String> getSkills() { 
        return Collections.unmodifiableList(skills); // protect
    }
}

Q12
Medium

Explain Thread lifecycle. What is Deadlock and how do you prevent it?

Expected Answer

Thread states: NEW → RUNNABLE → RUNNING → (BLOCKED/WAITING/TIMED_WAITING) → TERMINATED

Deadlock: Two or more threads waiting forever for each other's locks.

// Thread 1: locks A, then tries to lock B
// Thread 2: locks B, then tries to lock A
// Both stuck forever!

Prevention:

  • Lock ordering — Always acquire locks in the same order
  • Lock timeout — Use tryLock() with timeout
  • Avoid nested locks — Minimize lock scope
  • Use java.util.concurrent classes — ReentrantLock, Semaphore

Quick-fire Core Java Questions (practice answering in 30 seconds each):

Quick Answers

Q13. Abstract class vs Interface?
Abstract: partial abstraction, has constructors, can have state. Interface: full abstraction (Java 8+ has default methods), no constructors, no state. Use interface for "can-do" (Serializable), abstract for "is-a" (Vehicle).

Q14. ArrayList vs LinkedList?
ArrayList: O(1) random access, O(n) insert/delete middle. LinkedList: O(n) access, O(1) insert/delete. Use ArrayList 95% of the time (cache-friendly).

Q15. String vs StringBuilder vs StringBuffer?
String: immutable. StringBuilder: mutable, NOT thread-safe (faster). StringBuffer: mutable, thread-safe (slower). Use StringBuilder in single-threaded code.

Q16. What is Singleton pattern? How to make it thread-safe?
Only one instance of a class. Use: private constructor + static method. Thread-safe: Bill Pugh (inner static class), enum Singleton, or double-checked locking with volatile.

Q17. What is volatile keyword?
Ensures variable is read from main memory, not thread's cache. Provides visibility guarantee but NOT atomicity. Use for flags/booleans shared between threads.

Q18. Comparable vs Comparator?
Comparable: natural ordering, class implements it, single sort. Comparator: external, multiple sort criteria, used with Collections.sort() or stream.sorted().

Q19. What are Generics? Why use them?
Type safety at compile time. Eliminates ClassCastException. Example: List<String> vs raw List. Type erasure: generics exist only at compile time.

Q20. What is try-with-resources?
Auto-closes resources implementing AutoCloseable. No need for finally block. Example: try (Connection conn = getConnection()) { ... } — conn auto-closed.

What are the 4 built-in Functional Interfaces? Give examples.

Expected Answer

// 1. Predicate<T> — Takes T, returns boolean (testing)
Predicate<Integer> isEven = n -> n % 2 == 0;

Q3
Easy🔥 Asked Every Time

Explain Stream API. What is the difference between intermediate and terminal operations?

Expected Answer

Stream: A sequence of elements processed in a pipeline. Does NOT modify the source. Lazy evaluation — intermediate ops execute only when terminal op is called.

Intermediate operations (return Stream, lazy): filter(), map(), flatMap(), distinct(), sorted(), peek(), limit(), skip()

Terminal operations (produce result, trigger execution): collect(), forEach(), reduce(), count(), findFirst(), findAny(), anyMatch(), allMatch(), noneMatch(), toArray()

// Pipeline example
List<String> result = employees.stream()     // source
    .filter(e -> e.getSalary() > 50000)       // intermediate
    .map(Employee::getName)                    // intermediate
    .sorted()                                  // intermediate
    .collect(Collectors.toList());             // terminal (triggers all)

Stream vs Collection: Collection stores data (eager). Stream processes data (lazy). Stream can only be consumed once!

Q9
MediumFrequent

What is Optional? How do you use it properly?

Expected Answer

Optional is a container that may or may not contain a value. Designed to prevent NullPointerException.

// Creating
Optional<String> empty = Optional.empty();
Optional<String> name = Optional.of("Hasbrovish");  // throws if null
Optional<String> maybe = Optional.ofNullable(null);  // safe

// Using (NEVER do optional.get() directly!)
String result = maybe.orElse("default");
String result2 = maybe.orElseGet(() -> computeDefault());
maybe.orElseThrow(() -> new RuntimeException("Not found"));

// Chaining
String city = employee
    .map(Employee::getAddress)
    .map(Address::getCity)
    .orElse("Unknown");

// ❌ BAD: optional.isPresent() + optional.get()
// ✅ GOOD: optional.orElse() or optional.map()

Quick-fire Java 8 Questions:

Quick Answers

Q10. map() vs flatMap()?
map(): 1-to-1 transformation. flatMap(): 1-to-many, then flattens. Use flatMap when each element produces a stream.

Q11. What is method reference? Types?
Shorthand for lambda. Types: Static (Math::abs), Instance (String::length), Constructor (ArrayList::new), Particular object (System.out::println)

Q12. Default methods in interfaces — what if two interfaces have same default method?
Compile error! Class must override and specify which: InterfaceA.super.method()

Q13. What is parallelStream()?
Splits work across ForkJoinPool threads. Use for large datasets, CPU-intensive operations. Avoid for I/O ops or when order matters. Not always faster!

Q14. peek() vs forEach()?
peek() is intermediate (for debugging), forEach() is terminal. peek() is lazy, forEach() triggers execution.

Q15. reduce() example?
int sum = list.stream().reduce(0, Integer::sum); Takes identity + accumulator. Optional version: list.stream().reduce(Integer::sum)

    }

Q3
Medium🔥 Very Frequent

Explain Dependency Injection. What is the best way to inject dependencies?

Expected Answer

DI: Dependencies are provided to a class externally rather than the class creating them itself. Promotes loose coupling and testability.

3 types of injection:

  • Constructor Injection (BEST ✅): Dependencies via constructor. Ensures all required deps are provided. Supports immutability (final fields). Recommended by Spring team.
  • Setter Injection: Via setter methods. For optional dependencies.
  • Field Injection (AVOID ❌): @Autowired on field directly. Hard to test, hides dependencies.
// ✅ BEST: Constructor injection (no @Autowired needed since Spring 4.3)
@Service
public class TaxService {
    private final TaxRepository taxRepo;
    private final NotificationService notifService;
    
    public TaxService(TaxRepository taxRepo, 
                      NotificationService notifService) {
        this.taxRepo = taxRepo;
        this.notifService = notifService;
    }
}

Rapid-fire Spring Boot Questions (14 questions):

All Answers

Q4. @Qualifier vs @Primary?
When multiple beans of same type exist: @Primary marks the default one. @Qualifier explicitly specifies which bean by name. @Qualifier overrides @Primary.

Q5. Bean Scopes?
singleton (default—one per container), prototype (new each request), request (per HTTP request), session (per HTTP session), application (per ServletContext).

Q6. Spring Profiles?
Environment-specific configs. application-dev.yml, application-prod.yml. Activate: spring.profiles.active=dev. Use @Profile("dev") on beans.

Q7. @Transactional — how does it work?
AOP-based proxy wrapping. Starts transaction before method, commits on success, rolls back on RuntimeException. Set propagation (REQUIRED, REQUIRES_NEW) and isolation levels.

Q8. @Component vs @Service vs @Repository?
All are @Component specializations. @Service: business logic (no extra behavior). @Repository: DAO layer + auto-translates DB exceptions to Spring exceptions. Use them for clarity and specific features.

Q9. How CRUD works in Spring Boot?
Client → @RestController (receives request) → @Service (business logic) → @Repository (extends JpaRepository) → Database. Response flows back through same layers.

Q10. Exception handling in Spring Boot?
@ControllerAdvice + @ExceptionHandler for global handling. Return ResponseEntity with proper status code and error body. Custom exception classes extending RuntimeException.

Q11. Spring AOP annotations?
@Aspect (marks AOP class), @Before, @After, @AfterReturning, @AfterThrowing, @Around (most powerful — controls method execution). Use for logging, security, transactions.

Q12. Spring Boot Actuator?
Production-ready features: /health, /info, /metrics, /env endpoints. Monitor application health, track metrics, check environment properties.

Q13. How to connect Hibernate to Spring Boot?
Add spring-boot-starter-data-jpa dependency. Configure in application.properties: spring.datasource.url, username, password, spring.jpa.hibernate.ddl-auto. Create @Entity classes and Repository interfaces.

Q14. JPA Entity lifecycle?
Transient (new, not managed) → Persistent (managed by EntityManager, changes tracked) → Detached (session closed, not tracked) → Removed (marked for deletion).

Q15. Lazy vs Eager loading?
Eager: loads related entities immediately (default for @ManyToOne). Lazy: loads on first access (default for @OneToMany). N+1 Problem: Lazy loading in a loop fires N extra queries. Fix: JOIN FETCH or @EntityGraph.

Q16. Spring Security basics?
Authentication (who are you) + Authorization (what can you do). Filter chain intercepts requests. JWT for stateless auth. @PreAuthorize for method-level security.

Q17. application.properties vs application.yml?
Both configure Spring Boot. yml is hierarchical/readable. properties is flat key=value. yml supports profiles in single file with ---.

Q18. How to handle validation?
@Valid + javax.validation annotations: @NotNull, @NotBlank, @Size, @Email, @Min, @Max. BindingResult captures errors. Custom validators with @Constraint.

Microservices Architecture

Important for 5+ years experience. Relate everything to your GSTN project!

Q1-10
Medium

Complete Microservices Question Bank:

All Answers

Q1. Monolith vs Microservices?
Monolith: single deployable unit, easier to start, harder to scale. Microservices: independent services, independently deployable, tech flexibility, but adds complexity (networking, data consistency). Choose microservices when: team is large, need independent scaling, different parts change at different speeds.

Q2. How do microservices communicate?
Synchronous: REST (HTTP), gRPC. Asynchronous: Message queues (Kafka, RabbitMQ). Use async for: event-driven flows, decoupling, reliability. Use sync for: real-time responses, simple request-reply.

Q3. What is API Gateway?
Single entry point for all clients. Handles: routing, authentication, rate limiting, load balancing, SSL termination. Tools: Spring Cloud Gateway, Kong, Zuul.

Q4. Service Discovery — how do services find each other?
Services register with a discovery server (Eureka). Clients query Eureka to find service instances. Client-side (Ribbon) or Server-side load balancing. No hardcoded URLs!

Q5. Circuit Breaker pattern?
Prevents cascading failures. States: CLOSED (normal) → OPEN (fails fast, no calls) → HALF_OPEN (tests recovery). Tool: Resilience4j. Fallback method returns default response when service is down.

Q6. How to handle distributed transactions?
Saga Pattern: sequence of local transactions with compensating transactions on failure. Choreography (event-based) or Orchestration (central coordinator). Avoid 2PC in microservices — too slow.

Q7. What is Feign Client?
Declarative REST client. Write interface + annotations, Spring creates implementation. Simplifies inter-service calls. Integrates with Eureka for service discovery.

Q8. How to manage configuration?
Spring Cloud Config Server: centralized config for all services. Stores in Git. Supports environment-specific configs. @RefreshScope for dynamic updates.

Q9. Docker basics for microservices?
Each service → separate Docker image → separate container. Dockerfile: FROM openjdk → COPY jar → ENTRYPOINT. docker-compose: define all services, networks, volumes. Health checks: HEALTHCHECK instruction.

Q10. How to manage faulty containers in Docker?
docker logs (check errors), docker restart, health checks in docker-compose, restart policies (restart: always/on-failure), monitoring with Prometheus/Grafana. Kubernetes: auto-healing with liveness/readiness probes.

🎯 GSTN Connection: When answering, say: "In GSTN, we use [pattern] for [specific use case]. For example, during GST filing deadlines when we handle 100K+ concurrent requests, our circuit breaker prevents cascading failures if the authentication service is overloaded."

Q1-10
Medium🔥 Top Queries Asked

Must-Know SQL Queries — Write from memory!

All Solutions

Q1. Find employee(s) with highest salary:

SELECT * FROM employees 
WHERE salary = (SELECT MAX(salary) FROM employees);

Q2. Find 2nd highest salary:

-- Method 1: Subquery
SELECT MAX(salary) FROM employees 
WHERE salary < (SELECT MAX(salary) FROM employees);

-- Method 2: DENSE_RANK (handles ties correctly)
SELECT * FROM (
    SELECT *, DENSE_RANK() OVER (ORDER BY salary DESC) as rnk 
    FROM employees
) t WHERE rnk = 2;

-- Method 3: LIMIT/OFFSET
SELECT DISTINCT salary FROM employees 
ORDER BY salary DESC LIMIT 1 OFFSET 1;

Q3. Nth highest salary:

SELECT * FROM (
    SELECT *, DENSE_RANK() OVER (ORDER BY salary DESC) as rnk 
    FROM employees
) t WHERE rnk = N;

Q4. Find duplicates:

SELECT email, COUNT(*) as cnt FROM employees 
GROUP BY email HAVING COUNT(*) > 1;

Q5. Department-wise highest salary:

SELECT department, MAX(salary) as max_salary 
FROM employees GROUP BY department;

-- With employee details:
SELECT * FROM (
    SELECT *, ROW_NUMBER() OVER (
        PARTITION BY department ORDER BY salary DESC
    ) as rn FROM employees
) t WHERE rn = 1;

Q6. Employees who earn more than their manager:

SELECT e.name FROM employees e 
JOIN employees m ON e.manager_id = m.id 
WHERE e.salary > m.salary;

Q7. DELETE duplicates keeping only one:

DELETE FROM employees WHERE id NOT IN (
    SELECT MIN(id) FROM employees GROUP BY email
);

Q8. INNER vs LEFT vs RIGHT vs FULL JOIN?
INNER: only matching rows. LEFT: all from left + matching right. RIGHT: all from right + matching left. FULL: all from both tables.

Q9. WHERE vs HAVING?
WHERE filters rows BEFORE grouping. HAVING filters groups AFTER GROUP BY. HAVING can use aggregate functions, WHERE cannot.

Q10. Index — what and when?
Data structure to speed up queries. B-Tree index for equality/range. Use on: frequently queried columns, JOIN columns, WHERE conditions. Avoid on: small tables, frequently updated columns.

Transform displayed data. Built-in: date, uppercase, lowercase, currency, json, async. Custom: implement PipeTransform interface. Pure (default, cached) vs Impure (runs on every change detection).

Q5. Component lifecycle hooks?
ngOnInit (after first ngOnChanges), ngOnChanges (input changes), ngDoCheck, ngAfterViewInit, ngOnDestroy (cleanup subscriptions!). Most used: ngOnInit for API calls, ngOnDestroy for unsubscribing.

Q6. Observable vs Promise?
Promise: single async value, eager (executes immediately), not cancellable. Observable: stream of values, lazy (needs subscribe), cancellable (unsubscribe), supports operators (map, filter, switchMap).

Q7. What is RxJS?
Reactive Extensions for JS. Used in Angular for HTTP calls, event handling. Key operators: map, filter, switchMap, mergeMap, catchError, debounceTime, distinctUntilChanged.

JavaScript Questions

Q9. var vs let vs const?
var: function-scoped, hoisted, re-declarable. let: block-scoped, not hoisted, not re-declarable. const: block-scoped, not reassignable (but objects/arrays mutable).

Q10. What are closures?
Function that has access to outer function's variables even after outer function has returned. Used for: data privacy, factory functions, callbacks.

Q11. Promises and async/await?
Promise: .then().catch(). async/await: syntactic sugar over Promises, makes async code look synchronous. try/catch for error handling.

Q12. == vs ===?
==: loose equality (type coercion). ===: strict equality (no coercion). Always use === in production code. Examples: "5" == 5 is true, "5" === 5 is false.

Two Sum: Find two numbers in an array that add up to target.

Input: nums = [2, 7, 11, 15], target = 9
Output: [0, 1] (because nums[0] + nums[1] = 9)

Solution — O(n) using HashMap

public int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> map = new HashMap<>();
    for (int i = 0; i < nums.length; i++) {
        int complement = target - nums[i];
        if (map.containsKey(complement)) {
            return new int[] { map.get(complement), i };
        }
        map.put(nums[i], i);
    }
    return new int[] {}; // no solution
}
// Time: O(n), Space: O(n)

Key insight: Store each number's index in a HashMap. For each element, check if its complement (target - current) exists in the map.

// Approach 1: Using HashSet — O(n)
public List<Integer> findDuplicates(int[] nums) {
    Set<Integer> seen = new HashSet<>();
    Set<Integer> duplicates = new HashSet<>();
    for (int num : nums) {
        if (!seen.add(num)) {  // add() returns false if exists
            duplicates.add(num);
        }
    }
    return new ArrayList<>(duplicates);
}

// Approach 2: Using Streams — Java 8
public List<Integer> findDuplicatesStream(int[] nums) {
    return Arrays.stream(nums).boxed()
        .collect(Collectors.groupingBy(
            Function.identity(), Collectors.counting()))
        .entrySet().stream()
        .filter(e -> e.getValue() > 1)
        .map(Map.Entry::getKey)
        .collect(Collectors.toList());
}

Reverse a Linked List.

Solution — Iterative O(n)

public ListNode reverseList(ListNode head) {
    ListNode prev = null;
    ListNode curr = head;
    while (curr != null) {
        ListNode next = curr.next;  // save next
        curr.next = prev;           // reverse pointer
        prev = curr;                // advance prev
        curr = next;                // advance curr
    }
    return prev;  // new head
}
// Trick: 3 pointers — prev, curr, next
// Time: O(n), Space: O(1)

// Two pointer approach — O(n), O(1) space
public boolean isPalindrome(String s) {
    s = s.toLowerCase().replaceAll("[^a-z0-9]", "");
    int left = 0, right = s.length() - 1;
    while (left < right) {
        if (s.charAt(left) != s.charAt(right)) return false;
        left++; right--;
    }
    return true;
}

// Using StringBuilder — simpler but O(n) space
public boolean isPalindromeSimple(String s) {
    String clean = s.toLowerCase().replaceAll("[^a-z0-9]", "");
    return clean.equals(new StringBuilder(clean).reverse().toString());
}

Implement a Stack using arrays. Include push, pop, peek, isEmpty.

Solution

public class MyStack {
    private int[] arr;
    private int top;
    private int capacity;
    
    public MyStack(int size) {
        arr = new int[size];
        capacity = size;
        top = -1;
    }
    
    public void push(int val) {
        if (top == capacity - 1) 
            throw new StackOverflowError("Stack is full");
        arr[++top] = val;
    }
    
    public int pop() {
        if (isEmpty()) 
            throw new EmptyStackException();
        return arr[top--];
    }
    
    public int peek() {
        if (isEmpty()) 
            throw new EmptyStackException();
        return arr[top];
    }
    
    public boolean isEmpty() { return top == -1; }
    public int size() { return top + 1; }
}

    if (nums.length == 0) return 0;
    int j = 0;
    for (int i = 1; i < nums.length; i++) {
        if (nums[i] != nums[j]) nums[++j] = nums[i];
    }
    return j + 1;
}

public int fib(int n) {
    if (n <= 1) return n;
    int a = 0, b = 1;
    for (int i = 2; i <= n; i++) {
        int temp = a + b; a = b; b = temp;
    }
    return b;
}

C12. Merge two sorted arrays:

public int[] merge(int[] a, int[] b) {
    int[] result = new int[a.length + b.length];
    int i = 0, j = 0, k = 0;
    while (i < a.length && j < b.length)
        result[k++] = a[i] <= b[j] ? a[i++] : b[j++];
    while (i < a.length) result[k++] = a[i++];
    while (j < b.length) result[k++] = b[j++];
    return result;
}

public boolean isValid(String s) {
    Stack<Character> stack = new Stack<>();
    for (char c : s.toCharArray()) {
        if (c == '(') stack.push(')');
        else if (c == '{') stack.push('}');
        else if (c == '[') stack.push(']');
        else if (stack.isEmpty() || stack.pop() != c) return false;
    }
    return stack.isEmpty();
}
